# 视觉 Token 压缩对多模态推理长度影响的扩展验证实验方案

**版本：V1.0｜2026-10-27**

## 1. 实验目标

本轮实验的主要目的，是在更多模型、数据集、压缩方法和压缩率下，验证此前实验中观察到的现象：视觉 Token 压缩可能导致多模态 Thinking 模型生成更多推理 Token，部分样本出现超过两倍的推理长度增长。

研究以下四个问题：

- **RQ1：现象普遍性。** 不同模型、压缩方法、任务和压缩率下，推理 Token 是否系统性增长？
- **RQ2：增长规律。** 推理长度增长是否随视觉 Token 保留率下降而增强？不同压缩方法之间是否存在明显差异？
- **RQ3：能力与效率关系。** 在模型仍能正确回答问题时，是否也会发生显著推理长度增长？
- **RQ4：异常增长。** 推理长度超过两倍的样本占比、分布、正确性及任务类型有什么规律？

本轮以**定量现象验证和轨迹数据收集**为主，同时对部分异常轨迹进行定性分析，为下一轮机制实验提供依据。

不在本轮进行模型训练、额外蒸馏或针对性 Prompt 优化。

## 2. 模型、压缩方法与压缩率

### 2.1 基础模型

| 模型 | Hugging Face ID | 角色 |
|---|---|---|
| Qwen3-VL-4B-Thinking | `Qwen/Qwen3-VL-4B-Thinking` | 小规模 Thinking 模型 |
| Qwen3-VL-8B-Thinking | `Qwen/Qwen3-VL-8B-Thinking` | 规模扩展验证 |

统一要求：

- 使用官方原始 BF16 权重，不对模型额外量化。
- 使用各模型官方 Processor、Tokenizer 和 Chat Template。
- 保留原生 Thinking 模式。
- 同一模型的所有实验必须使用完全相同的权重、图像预处理方式和 Prompt。
- 记录模型 revision、权重版本、Tokenizer 版本及 Transformers Commit。

### 2.2 压缩方法

| 方法 | 实现来源 | 主要说明 |
|---|---|---|
| PriorTR | PriorTR 的 Qwen3-VL 实现 | 基于先验校正的 Token 重要性评分 |
| FastV | PriorTR 移植 | 根据注意力分数选择保留 Token |
| VisPruner | PriorTR 移植 | 根据重要性与多样性选择 Token |
| SparseVLM | PriorTR 移植 | 动态选择，可包含 Token Merge |
| Hi-Lo Prune | 独立官方仓库 | 分层筛选并融合部分待删除 Token 的信息 |

**重要实施要求：**

PriorTR 仓库提供 Qwen3-VL 上前四种方法的统一接口，应优先使用这一实现，避免重复移植造成额外误差。

Hi-Lo Prune 需要使用其独立实现并进行适配。当前公开代码主要覆盖 Qwen3-VL-8B 的单图推理，必须先完成与 4B/8B Thinking 模型的兼容性测试。

所有方法均需要执行 No-Pruning 对照，验证关闭剪枝时与原始模型的输出一致。

### 2.3 保留率

按照草案设置：

| 保留率 | 删除率 | 用途 |
|---|---|---|
| 100% | 0% | 原始模型 Baseline |
| 90% | 10% | 轻度压缩 |
| 75% | 25% | 中轻度压缩 |
| 50% | 50% | 中度压缩 |
| 25% | 75% | 高压缩 |
| 10% | 90% | 极端压缩 |

100% 必须直接关闭剪枝模块，不能仅仅将剪枝器的 `keep_ratio` 设为 1。

每个模型的 100% Baseline 只需要运行一次，同一批题目上的结果由所有方法共享。

**保留率定义：**

以进入多模态语言模型、即将被剪枝的视觉 Token 数量为分母。

\[
r_{\mathrm{actual}}=\frac{N_{\mathrm{retained}}}{N_{\mathrm{original}}}
\]

其中：

- `N_original`：剪枝前的视觉 Token 数；
- `N_retained`：实际保留下来、继续进入后续层的视觉 Token 数；
- `r_actual`：实际保留率。

每条样本都必须保存这三个值。

不同方法因 Token Merge、舍入、受保护 Token 或剪枝层位置不同，实际保留率可能略有差异。报告中应同时给出目标保留率与实际保留率。

不能将“不同方法使用同样的目标保留率”直接等价于“其计算成本完全相同”。

## 3. 数据集与抽样方案

### 3.1 数据集

保留六个数据集，每个正式抽取 150 道题。

| 数据集 | 测试划分 | 题量 | 抽样要求 |
|---|---|---:|---|
| ChartQA | test | 150 | Human 75、Augmented 75 |
| MMMU | validation | 150 | 六大学科各 25，优先单图样本 |
| MathVista | testmini | 150 | 按任务类型分层抽样 |
| MathVerse | testmini | 150 | 使用 Vision Dominant 版本，150 道不同原题 |
| GQA | val_balanced | 150 | 覆盖关系、属性、对象等题型 |
| AI2D | test | 150 | 尽量覆盖不同科学图解类别 |
| **合计** | | **900** | |

采用以下固定规则：

1. 每个数据集先准备 20 道独立测试题，用于环境与推理配置检查，不纳入正式统计。
2. 正式测试集抽取 150 道，与预实验样本不重复。
3. 抽样 seed 固定为 42。
4. 同一模型的所有方法、保留率使用完全相同的 150 道题。
5. 两个模型同样使用相同的样本清单。
6. 抽样完成后保存 `manifest.jsonl`，以后不得根据模型表现重新抽样。

特别处理：

- **MathVerse**：五种文本/视觉版本来自相同原题。本轮主实验只抽取 Vision Dominant，避免将同一题的多个版本当成独立题。
- **ChartQA**：Human 和 Augmented 两部分分别抽样，报告总体结果时也分别报告这两个子集。
- **MMMU**：由于 Hi-Lo 当前实现有单图限制，主实验只保留可由所有方法共同处理的单图题。如果某一学科单图数量不足，则按其他学科剩余单图数量补齐，并记录实际学科分布。
- **GQA 和 AI2D**：尽可能按不同图像抽样，避免同一图像上的多个高度相关问题重复出现。

所有过滤操作必须在模型推理前完成，不能根据模型是否答对、推理长度是否异常来决定保留哪些题。

### 3.2 数据清单

每个样本应包含：

| 字段 | 内容 |
|---|---|
| `sample_id` | `dataset:split:original_id` |
| `dataset` | 数据集名称 |
| `split` | 测试划分 |
| `question` | 原始问题 |
| `choices` | 选择题选项，没有则为空 |
| `gold_answer` | 标准答案 |
| `question_type` | 题型 |
| `task_type` | 任务类别 |
| `image_paths` | 图像路径 |
| `image_count` | 图像数量 |
| `image_hash` | 原图 SHA256 |
| `source_id` | 原始题目或图像组 ID |

图像需要保留原始内容，不进行额外裁剪、OCR、视觉增强或人工标注。

由模型官方 Processor 完成图像预处理，并记录预处理参数及实际图像 Token 数量。

## 4. 推理参数和确定性检查

### 4.1 主实验解码设置

按照草案，主实验首先采用确定性贪心解码：

| 参数 | 设置 |
|---|---|
| Temperature | 0 |
| `do_sample` | False |
| `num_beams` | 1 |
| `num_return_sequences` | 1 |
| `max_new_tokens` | 32,768 |
| Repetition Penalty | 1.0 |
| Presence Penalty | 0 |
| Seed | 42 |
| Batch Size | 1 |
| Thinking | Enabled |

所有模型和方法使用相同生成参数。

这里需要特别说明，Qwen3-VL-Thinking 官方的推荐配置是 Temperature=1.0、Top-p=0.95、Top-k=20，且采用采样而不是贪心解码。因此必须验证 Temperature=0 本身是否引起不正常重复。

### 4.2 贪心解码预检查

在正式测试前，对两个原始模型分别运行每个数据集的 20 道预实验题。

保存：

- CoT Token 数；
- 输出是否正常结束；
- 是否达到最大生成长度；
- 是否存在重复生成循环；
- 准确率与答案解析成功率。

重复生成循环的自动预警规则：

在生成文本的最后 2,048 Token 中，存在长度不小于 80 Token 的完全相同片段，且连续或间隔重复出现至少三次。

被自动标记的轨迹需要人工确认。

如果一个模型在 120 道预实验题中，有超过 5% 的题目达到生成上限，或者经确认发生明显生成循环，则停止该模型的 Temperature=0 大规模运行，并改用官方采样配置作为主实验设置；Temperature=0 结果保留为解码敏感性分析。

这一决策必须在查看正式测试集结果之前完成并记录。

### 4.3 剪枝方法的确定性检查

对五种方法，在保留率 75%、50%、25% 下抽取 10 道预实验题，每个配置重复运行三次：

- 固定所有随机种子；
- 比较所选视觉 Token 的位置；
- 比较实际保留 Token 数量；
- 比较生成的 Token ID 序列；
- 比较最终答案和推理长度。

若结果发生变化，应区分：

1. 压缩算法自身的随机性；
2. GPU 算子或推理框架造成的非确定性；
3. 解码时的随机采样。

确定性设置下的差异必须记录，不允许直接当成多次独立实验的误差。

## 5. 推理输出与日志保存

每次生成都保存完整的逐样本数据，不允许只保存聚合结果。

### 5.1 基础信息

| 字段 | 含义 |
|---|---|
| `run_id` | 唯一运行标识 |
| `sample_id` | 样本 ID |
| `model_id` | 模型与版本 |
| `method` | 压缩方法 |
| `keep_ratio_target` | 目标保留率 |
| `keep_ratio_actual` | 实际保留率 |
| `seed` | 生成种子 |
| `decoding_config` | 完整解码参数 |
| `prompt_hash` | 完整 Prompt 的哈希 |
| `model_revision` | 权重版本 |
| `code_commit` | 实验代码版本 |

### 5.2 视觉压缩信息

保存：

- `visual_tokens_original`
- `visual_tokens_retained`
- `visual_tokens_removed`
- `prune_layer`
- `selected_visual_token_indices`
- `merge_enabled`
- `merged_token_count`
- `image_grid_shape`
- `image_processor_config`

对于不同层剪枝的方法，记录剪枝前后的实际序列长度及所在层。

对于 Hi-Lo 和 SparseVLM 等可能融合信息的方法，需要分别记录 Token 删除与融合行为，避免把融合后的表示误算为原始 Token。

### 5.3 推理输出

| 字段 | 含义 |
|---|---|
| `raw_generated_token_ids` | 完整生成 Token ID |
| `raw_response` | 包含特殊标记的原始输出 |
| `reasoning_trace` | 思维链内容 |
| `final_answer_text` | 最终回答 |
| `predicted_answer` | 解析后的答案 |
| `correct` | 是否正确 |
| `reasoning_tokens` | CoT Token 数 |
| `answer_tokens` | 最终答案 Token 数 |
| `total_output_tokens` | 总输出 Token 数 |
| `finish_reason` | 正常完成、长度上限或异常终止 |
| `think_parse_status` | 思维链是否成功分割 |
| `latency_ms` | 实际生成耗时 |

**推理 Token 必须通过原始 Token ID 计数。**

优先按 Tokenizer 中的 `</think>` 特殊 Token 边界，将生成序列拆分为 Thinking 和最终回答两部分。要处理 Prompt 已经包含 `<think>` 前缀的情况。

如果缺少正常的 Thinking 结束标记，保留完整原始序列，并设置解析状态为异常，不能直接将全部输出视为最终答案。

### 5.4 数据格式

每条实验结果保存为 JSONL，聚合分析时可以转换为 Parquet。

同时保存原始图像引用、Prompt、代码版本和模型版本。

禁止后处理脚本覆盖原始推理轨迹。

## 7. 实验运行安排

### 阶段 0：实现检查与环境验证

目的：先排除代码问题。

需要完成：

- 两款 Thinking 模型在 PriorTR 和 Hi-Lo 代码中的加载验证。
- 五种方法在 4B 和 8B 上的前向推理验证。
- No-Pruning 与官方原始模型的输出和 Logits 对齐验证。
- 每种方法真实保留率及剪枝层验证。
- Thinking / Answer 正确分离。
- 完整的答案评分与原始日志保存验证。
- 确定性检查。

必须通过后才能开始正式实验。

### 阶段 1：小规模先导实验

每个数据集的 20 道预实验题，使用两个模型。

首先测试三个最重要的压缩率：

**75%、50%、25%。**

对应配置：

- 2 个模型；
- 6 个数据集；
- 每个数据集 20 题；
- 5 个方法；
- 3 档压缩率；
- 1 组共享 Baseline。

运行次数：

\[
2\times6\times20\times(1+5\times3)=3840
\]

先导实验输出：

1. 基线推理长度分布。
2. 每种方法的准确率、CTIR。
3. 正常结束率和截断率。
4. 超过两倍的轨迹数量。
5. 不同方法的实际视觉 Token 数量。
6. 按模型、数据集和压缩率估计正式实验的计算需求。

先导结果用于判断代码和运行成本，不允许用来有针对性地调整正式测试集题目。

### 阶段 2：正式全量实验

每个数据集 150 道题，全部六档保留率。

100% 共享 Baseline，不按压缩方法重复运行。

| 项目 | 数量 |
|---|---:|
| 模型 | 2 |
| 数据集 | 6 |
| 每数据集题数 | 150 |
| 剪枝方法 | 5 |
| 非 Baseline 保留率 | 5 |
| 单个模型配置数 | 26 |
| **正式总推理次数** | **46,800** |

其中：

- Baseline 推理：1,800 次；
- 压缩推理：45,000 次。

按照以下优先顺序运行：

1. 两款模型的全部 Baseline；
2. 75%、50%、25% 保留率；
3. 90%、10% 保留率；
4. 异常样本补充验证。

正式样本清单、Prompt 和评分方式应在运行前冻结。

### 阶段 3：随机性与解码鲁棒性实验

为避免全部配置重复三次造成过高计算开销，选择代表性子集进行独立采样验证。

固定使用：

- 模型：4B、8B；
- 数据集：MathVista、ChartQA；
- 每个数据集 60 道正式测试题；
- 方法：PriorTR、FastV；
- 保留率：100%、50%、25%；
- 生成种子：42、43、44；
- Temperature：1.0；
- Top-p：0.95；
- Top-k：20。

每道题的 Baseline 在三个种子上各运行一次，并为四个剪枝配置分别生成对应结果。

总推理次数：

\[
2\times2\times60\times(1+2\times2)\times3
=1800
\]

报告跨种子的 CTIR、准确率变化、超两倍比例，以及与 Temperature=0 结果的差别。

如果阶段 0 判定 Temperature=0 不适用，则官方采样配置成为正式主设置；此时需要按照实际随机性重新安排核心配置的多种子运行，不能继续把单种子结果当成确定性结果。

### 阶段 4：异常轨迹分析

从正式实验中筛选：

- 原始与压缩模型都正确，但推理长度超过两倍；
- 原始正确、压缩错误，且推理长度超过两倍；
- 两者都错误、压缩后明显增长；
- 压缩后推理显著缩短的对照样本。

优先抽取 40–60 对有代表性的轨迹，覆盖不同任务和压缩方法。

分析维度包括重复验证、回溯、无效分支、重新计算、视觉证据不确定和提前停止失败。

每个案例均保留完整的 Baseline 与压缩轨迹，以及具体 Token 增量和输出正确性。

## 8. 核心统计指标

### 8.1 任务准确率

\[
A=\frac{\text{正确样本数量}}{\text{全部评测样本数量}}
\]

报告原始与压缩模型的准确率，以及准确率变化（百分点）。

### 8.2 平均推理长度与 CTIR

对同一数据集、同一模型、同一压缩配置：

\[
\mathrm{CTIR}=
\frac{\sum_i L_i^{compress}-\sum_i L_i^{base}}
{\sum_i L_i^{base}}\times100\%
\]

这是主要的总体计算成本指标。

跨六个数据集分别计算 CTIR，再使用六个任务等权的宏平均作为主要跨任务汇总指标。

### 8.3 单题长度变化率

\[
R_i=\frac{L_i^{compress}}{L_i^{base}}
\]

只对 Baseline 推理长度至少为 32 Token 的题目计算单题比值。

对于低于 32 Token 的题目，记录绝对增长量并单独报告，避免因分母过小产生夸张比值。

### 8.4 长度分布与异常率

每组至少报告：

| 统计指标 | 意义 |
|---|---|
| Mean CTIR | 整体 Token 成本增长 |
| Median Ratio | 典型样本增长 |
| P75、P90、P95 Ratio | 长尾增长情况 |
| `P(R≥1.5)` | 50% 以上增长的样本比例 |
| `P(R≥2)` | 超过两倍的比例 |
| `P(R≥3)` | 超过三倍的比例 |
| `P(R≥5)` | 极端增长比例 |
| Truncation Rate | 输出达到上限的比例 |
| Completion Rate | 正常完成推理的比例 |

所有长度比值相关指标必须说明有效分母和排除的极短 Baseline 样本数。

### 8.5 正确性分组

将配对样本分为：

| 组别 | Baseline | Compression |
|---|---|---|
| CC | 正确 | 正确 |
| CW | 正确 | 错误 |
| WC | 错误 | 正确 |
| WW | 错误 | 错误 |

四组分别报告样本数量、平均 CTIR、长度比值分布及严重增长比例。

其中 **CC 组是判断“最终能力不变但推理成本增加”的关键实验组**。

在计算 CC 组 CTIR 时，必须明确这是一种以双方都正确为条件的分析，不能代替完整测试集上的整体成本指标。

### 8.6 额外统计：视觉压缩与 Token 增量的关系

计算每题的绝对增长：

\[
\Delta L_i=L_i^{compress}-L_i^{base}
\]

并与实际视觉 Token 删除数量建立关联。

按实际保留率分组，比较：

- 绝对推理 Token 增量；
- CTIR；
- 准确率；
- 正常完成率。

同时观察是否出现非单调现象，例如 50% 保留率产生的增长反而高于 25%。

---

## 9. 统计误差与重复实验

### 9.1 主要统计方法

使用 **Paired Bootstrap**，以同一道题的 Baseline 和压缩结果作为不可拆分的配对单位。

设置：

- Bootstrap 次数：10,000；
- 重采样单位：`sample_id`；
- 每个数据集独立重采样；
- 随机种子：20261027；
- 置信水平：95%。

每次重采样都重新计算 CTIR、平均准确率差及其他配对指标。

使用 Bootstrap 分布的第 2.5 和 97.5 百分位数作为基本的 95% 置信区间。

对于跨六个数据集的 Macro-CTIR，应在每个数据集内部重采样，再计算六个 CTIR 的等权平均。

### 9.2 异常率的置信区间

严重增长比例使用 Wilson 二项比例置信区间。

对于极端增长比例接近 0 的情况，不使用正态近似区间。

### 9.3 多随机种子结果

采样实验分别报告三个种子的结果以及均值与标准差。

在进行题目级统计时，不能将同一道题在三个种子下的结果直接当成三道独立题。

主要采用以下方式：

1. 每个种子单独计算 CTIR；
2. 报告种子间的均值与标准差；
3. 按题目进行配对或层级 Bootstrap 作为补充。

### 9.4 显著性与结论标准

所有核心效应报告点估计和 95% CI。

对于事先确定的主要比较：

- FastV、PriorTR；
- 25% 保留率；
- 4B 和 8B；
- 六任务 Macro-CTIR；

使用配对 Bootstrap 判断 CTIR 的置信区间是否排除 0。

其他方法、压缩率和子任务分析作为探索性结果，必要时使用 Benjamini–Hochberg 方法控制多重比较的假发现率。

不能只依据某个配置的平均 CTIR 为正，就认定存在稳定的增长效应。

## 10. 数据质量与异常处理

### 10.1 最大生成长度

正式推理统一使用 `max_new_tokens=32768`。

达到长度上限的样本不删除、不重新抽样，也不将其视为正常推理结束。

分别统计：

- 正常完成样本的长度；
- 被截断样本的已生成长度；
- 截断率；
- 截断样本是否输出最终答案。

当某个配置的截断率超过 2% 时，需要将该配置标记为“长度结果受截断影响”，并通过提高生成上限的补充实验分析敏感性。

不能只删除长轨迹再计算 CTIR，因为这会系统性低估推理膨胀。

### 10.2 异常推理轨迹

保存并标记：

- 长度达到上限；
- 未产生正常 `</think>`；
- 未产生最终答案；
- 重复生成循环；
- 答案解析失败；
- 视觉 Token 保留数量异常；
- 推理进程出现 OOM 或其他异常。

不得把这些不同异常统一归为“模型回答错误”，必须同时保存独立的运行状态。

### 10.3 压缩实现一致性

在正式运行前，每种方法至少通过：

- 不剪枝时模型输出一致；
- 目标保留率实际生效；
- 视觉 Token 顺序和位置映射正确；
- 图像预处理一致；
- 文本 Token 不被错误剪除；
- 视觉 Token 数量与模型内部张量形状一致；
- 不同压缩率下无明显索引错误；
- Thinking / Answer 提取正确。

方法特有的参数使用官方实现默认值，并完整记录。

SparseVLM 是否启用 Merge、Hi-Lo 的融合策略、VisPruner 的剪枝位置等必须写入每次实验日志。

## 12. Agent 执行顺序与验收要求

建议采用以下脚本划分：

| 模块 | 职责 |
|---|---|
| `prepare_data.py` | 下载、过滤、分层抽样，生成 Manifest |
| `validate_backends.py` | 校验模型、剪枝方法和 No-Pruning 对齐 |
| `run_inference.py` | 按实验矩阵执行并保存完整输出 |
| `parse_outputs.py` | 提取 CoT、答案与 Token 统计 |
| `evaluate_answers.py` | 官方规则判分 |
| `aggregate_metrics.py` | CTIR、异常率、准确率等指标 |
| `statistical_analysis.py` | 配对 Bootstrap、多种子分析 |
| `analyze_trajectories.py` | 异常轨迹筛选与行为分类 |
| `generate_report.py` | 生成图表与报告 |

执行要求：

1. 先准备并冻结数据清单。
2. 通过所有代码正确性检查。
3. 运行独立先导实验。
4. 确定最终解码配置及生成上限。
5. 运行所有 Baseline。
6. 运行 75%、50%、25% 保留率。
7. 运行 90%、10% 保留率。
8. 完成统计与鲁棒性实验。
9. 分析异常轨迹并生成最终报告。

每个实验配置根据模型、数据集、样本、方法、保留率、解码模式和种子生成唯一 `run_id`。

运行过程支持中断恢复。已完成且校验通过的样本不得重复生成或覆盖。

**最终验收条件：**

- 正式样本清单已冻结，并可从原始 ID 复现。
- 每个配置都能确定实际视觉 Token 保留率。
- 无剪枝模型在对应适配框架中通过一致性验证。
- 每次生成的原始 Token ID、思维链和结束状态均已保存。
- 所有结果能够与共享 Baseline 按样本 ID 配对。
- 不静默删除失败、截断或无法解析的样本。
- 所有核心指标与报告均可以从原始 JSONL 独立重新计算。
- Hi-Lo 的 Thinking 模型适配未通过前，不得将其结果与其他方法做正式横向结论。

本轮实验的完成标准，不是单纯跑完全部配置，而是获得一套**完整、可重复、具有统计误差估计的压缩前后推理轨迹对照数据**，足以判断 Token Inflation 的普遍性、条件和异常分布。
